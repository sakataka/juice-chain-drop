# Juice Workshop: design

幻想的な果汁工房で、果物を搾って瓶詰めする落ち物パズル。盤面は果汁をためる搾り槽、水は果汁を薄める障害物として扱う。ルールの見た目も、この設定から外れないようにする。

## ゲームの循環

`CHAIN → PRESS → JUICE DROP → CHAIN` に、押し返す要素として水を加える。

- 連鎖するほど果汁がたまる。k連鎖目で消えた果物は1個あたり k 搾汁になり、難易度ごとの必要量（Easy 18 / Normal 24 / Hard 30）に達するとボトルが1本完成する。単発の消去だけではボトルはたまりにくい。
- ボトルは次の落下ピースとして盤面へ戻り、着弾すると果物ごとの効果で盤面を崩す。崩れた結果がつながれば、そのまま次の連鎖になる。
- `Normal` と `Score Attack` では、果物ペアを一定数置くごとに水が降る（`src/core/pressure.ts`）。1回に降る数は置いた手数に応じて上限なく増えるので、エンドレスプレイもいずれ終わる。時間ではなく手数で決めるため、手動でもAuto Playでも同じ圧力になる。
- 水は隣の果物を消すか、破壊系のボトルに巻き込んで取り除く。連鎖でボトルを作り、そのボトルで水を片付ける関係にする。

調整の目安は `bun run simulate:ai -- --mode normal --max-ms 900000`。2026-09 の調整時点では、Normal の Auto Play は3〜5分でゲームオーバーになり、盤面の平均最大高さは約7段、最大連鎖の中央値は5。Water Cleanup は16〜26秒でクリアする。

## 連鎖の再生

ルールは一瞬で解決し、再生用のフレームだけを残す。演出を待つためにルールを分割しない。

1. `resolveBoardRules(..., { recordFrames: true })` は、着地（settle）、ボトルの破裂（burst）、各連鎖の消去（pop）と落下（collapse。落下元と落下先を含む）を順に記録する。AIの探索では記録しない。
2. `GameSession` は `buildResolvePlayback`（`src/session/resolvePlayback.ts`）でフレームを時間軸に並べ、`tick` で進める。各段階で clearPop・splash・sparkle・waterClear の cue を出し、再生中はピース入力と自動落下を止める。状態は `resolving` として表示し、Next Drop には次に出るピースを先頭に出す。
3. 何も消えない着地は再生しないので、手触りは遅くならない。水の投下とゲームオーバー表示は再生が終わってから行う。

## 盤面の見た目

- 盤面の固定部分（木枠、フェルト、格子）は一度だけ描く。セルは72個のスプライトを使い回し、描画ごとには作り直さない。落下はフレームの落下情報から動かし、着地時に弾ませる。
- 盤面の底には、次のボトルに最も近い果物の色で果汁がたまる。水位は搾汁の進み具合に合わせて上がり、連鎖で波立ち、瓶が完成すると下がる。
- どこかの列が危険な高さに達すると、槽の縁が赤く脈打つ。
- 演出レイヤーは、ベクター描画を1枚に共有し、スプライトは使い回し、文字は演出ごとに1回だけ生成する。演出がない間は何もしない。連鎖の表示は最新の段だけに出す。

## HUDと動き

1. Press Tank は果物ごとの搾汁進捗を示す。大きな瓶の着色は次の瓶の進捗、小さな瓶と `NEXT` の数は完成済みの在庫を表す。完成時に進捗が0へ戻っても、在庫と混同しないようにする。
2. Next Drop の横に、次に降る水の数と残り手数を出す。
3. Auto Playで遊んだ回は `Auto Best` として自分の記録とは別に保存し、表示の見出しも切り替える。
4. 着地した果物は280msかけて減衰しながら潰れて戻る。消去では果物を圧縮してから飛沫へつなぐ。瓶は進捗が上がると小さく、完成すると大きく弾む。
5. ゲーム内の Reduced Effects、またはOSの「視差効果を減らす」設定がオンのときは、動きとCanvas演出を抑える。その場合も、状態、瓶の色、数値、果汁の水位は表示する。連鎖の再生時間はゲームの進行に関わるので、演出を減らしても変えない。

## 素材

- 果物、果汁瓶、水滴のスプライト（`src/assets/sprites/lab/*-v3.png`）は、背景画を参照して Codex の画像生成で作った。果物は形で区別できるようにし、Berry はイチゴにしている。
- 効果音の cue は意味ごとに分けている（move、rotate、land、squish、chainChime、bottleFill、bottleBurst、waterDrop、waterClear、stageUp など）。みずみずしさの要は、jsfxr の短い合成音に重ねる、下降する正弦波の共鳴音（`liquidNote`）。果物ごと、連鎖の段ごとに音程を変える。SFX Forge で生成した `public/sfx` のサンプルは、合成セットになかった4種（ボトル着弾、水が降る、水が消える、スピードアップ）にだけ使い、同じ共鳴音を重ねる。一度すべてをサンプルに置き換えたところ液体らしさが失われたので、この構成に戻した。
- BGM（`src/audio/bgmComposition.ts`）は24小節の3部構成で、データだけを持つ。テンポは128（段階が上がると最大146）で、スウィングはかけず、裏拍の和音、8分のベース、スネアとハイハットで前に進む感じを出している。落ち着いた曲はパズルの速さに合わなかった。再生は Tone.js（`bgmPreview.ts`）、MIDIへの書き出しは `scripts/generate-bgm.ts` が行う。音量は旧曲に合わせてある。Tone は `getTransport()` を使う。

## 設定の反映

難易度とモードは、ゲーム開始時の値をその回のルールとして固定する。プレイ中の変更は次のゲームから反映し、設定パネルにその旨を表示する。

## 実装境界

- ルール（`src/core`）：盤面、消去、搾汁、水の圧力、再生用フレーム。描画・音・DOMには依存しない。
- 進行（`src/session`）：コマンドの結果、連鎖再生の時間軸、水の投下タイミング、記録の保存。音と演出は cue として返すだけにする。
- 描画（`src/render`）：`BoardRenderer` が盤面・果汁・警告を、`VisualEffectsRenderer` が一時的な演出を担当する。
- HUD（`src/ui`）：`HudController` はゲームの状態をそのまま表示し、`JuiceMotion` はDOMの一時的な装飾だけを持つ。
- BGMエンジン（Tone.js）は、最初に音を有効にしたときに読み込む。

## 検証

単体テスト、型チェックを含む build、E2Eを実行する。連鎖の再生とバランスは、単体テストとAIシミュレーションで確認する。見た目は実ブラウザで、デスクトップと 420×912 の両方を確認する。確認中は音を止める（Playwright は `--mute-audio`）。
