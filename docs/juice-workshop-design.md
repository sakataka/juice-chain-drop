# Juice Workshop: presentation design

幻想的な果汁工房を保ち、操作する果物と瓶に視線が集まるようにする。ゲームの盤面、消去条件、スコア、入力受付、落下・解決タイミングは変更しない。

## 視覚の優先順位

1. 深い緑の盤面を背景に、果物のシルエットを少し大きく表示する。
2. Press Tankを記録より上へ配置する。既存の瓶素材を使い、6種類を3列の棚に並べる。
3. 大きな瓶の着色部分は次の瓶の進捗、小さな傾いた瓶とNEXTの数は完成済みの在庫を示す。完成時に進捗が0へ戻っても在庫と混同しない。
4. 背景、ロゴ、木と真鍮の枠は既存素材を維持する。

## 動きと音

- 着地した果物は280msの減衰するつぶれ・復元を行う。セル位置や衝突判定は変えない。
- 消去cueでは100msだけ果物を圧縮表示し、既存の飛沫・連鎖演出へつなぐ。解決処理は待たせない。
- 進捗上昇時は瓶を小さく弾ませ、完成時は大きく弾ませる。消去位置から瓶、完成した瓶からNextへ、既存素材を使った短い軌跡を表示する。
- 軌跡は600ms、同時に最大6個。送り元・送り先が画面外なら省略する。終了、再開前のリセット、演出軽減切替時に装飾を破棄する。
- 着地、消去、瓶完成の既存SFXに、短く下降する正弦波の共鳴音を重ねる。既存の音量、ミュート、AudioContextの解放条件に従う。BGMの構成は維持する。
- ゲーム内Reduced EffectsまたはOSの動きを減らす設定で、新しい動きとCanvas演出を抑制する。状態、瓶の色、数値は表示する。

## 実装境界

`BoardRenderer`が前回描画との差から短い着地表現を管理し、`VisualEffectsRenderer`は既存のclearPop cueを使う。`HudController`はゲームの進捗と在庫をそのまま表示し、`JuiceMotion`はDOMの一時的な装飾のみを所有する。ルール・進行管理への新しい依存や演出待ちは追加しない。

## 検証

既存の単体テスト、型チェックを含むbuild、E2Eを実行する。瓶完成と次の瓶の進捗の区別、Restart時の装飾破棄、OSとゲーム内の演出軽減をE2Eで確認する。実ブラウザでデスクトップと420×912の表示・操作を確認する。
